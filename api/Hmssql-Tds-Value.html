Hmssql.Tds.Value

Description

How a value is delimited on the wire, apart from packets and from what is done with the value. A value is read in two steps: cellHead reads its delimiter, and the caller then says what it wants of the payload, which is all of it (wholeValueBytes), its pieces as they arrive (valueStream) or nothing (skipValue).

valueStream :: Cell -> Stream (Of ByteString) Parser () Source #

The value's payload as it arrives, in pieces. A PLP value's chunk headers are read here and never appear in the stream.

boundedValue :: Int -> Int -> Cell -> Parser (Either (Stream (Of ByteString) Parser ()) WholeValue) Source #

A value for a consumer: read whole (Right) if it is at most this many bytes, given the allocation bound of wholeValueBytes and the limit, or else its payload as it arrives (Left, as valueStream). A PLP value whose total isn't known (xml, and json) is read a chunk at a time until it ends within the limit; once a chunk would take it past, the stream starts with the chunks already read, so at most the limit is ever held. A whole value is Owned unless it lay in one payload, and a drain that takes over while it is read gives DiscardedValue.

data WholeValue Source #

A value read whole: NULL, present, or discarded because a drain took over the response while the value was being assembled.
