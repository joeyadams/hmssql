Description

Unchecked little-endian loads and stores through raw pointers. Use Hmssql.Tds.Bytes for bounds-checked reads from a ByteString.

Every operation needs a valid span of 2, 4 or 8 bytes at the given byte offset. A read needs memory that is initialized and readable, and a write needs memory that is writable and that nothing else expects to stay as it was. The caller keeps the allocation alive for the whole call and makes sure the offset arithmetic doesn't overflow. Nothing here checks a capacity, an initialization, an ownership or a lifetime.

Alignment is handled here: on targets known to load and store words at any address an operation is one word access, and elsewhere it goes byte by byte. The functions are public for codecs and transports written outside hmssql.
