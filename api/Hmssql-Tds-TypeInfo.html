data TypeInfo Source #

A type as the wire describes it (MS-TDS 2.2.5.4 TYPE_INFO): the token's type byte with its length, precision and scale, or collation, as the server sends it in COLMETADATA and a client sends it for a parameter. The wire has fewer types than T-SQL (int arrives as TIIntN 4 or TIInt4; json and vector as character types): Hmssql.SqlType names the declared type. RawParam takes one to send a value with a wire type of your choosing.

valueProblem :: TypeInfo -> RawBytes -> Maybe String Source #

Why a value can't be sent as a parameter of this type, if it can't: a lengthProblem, or an empty value of a type whose length prefix uses 0 for NULL (every BYTE-length type, and sql_variant), which the server would read as NULL.

typeInfoProblem :: TypeInfo -> Maybe String Source #

Why a parameter can't have this type, if it can't: a precision or scale SQL Server doesn't have (a decimal or numeric precision outside 1 through 38 or a scale above the precision, MS-TDS 2.2.5.5.1.3; a time, datetime2 or datetimeoffset scale above 7, 2.2.5.4.2), XML schema names too long for their length prefixes, or a CLR user-defined type, which hmssql doesn't send.

writeTypeInfo :: TypeInfo -> Builder Source #

TYPE_INFO (MS-TDS 2.2.5.6): the type byte, then what the type carries (a length, a precision and scale, a collation, names).

writeValue :: TypeInfo -> RawBytes -> Builder Source #

A value as RPC parameters carry it, after its TYPE_INFO: nothing for a type with no value, the bytes of a fixed-length type, else a length prefix (whose NULL spelling depends on the kind, LengthKind) and the bytes, or PLP chunks. Nothing is checked here: a value too long for its length prefix wraps, and an empty BYTE-length or sql_variant payload is written as NULL. putValue checks with valueProblem first; this is for values checked already.
