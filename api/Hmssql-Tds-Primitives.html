Reading values in place

type ValueReader a = ByteString -> Either String a Source #

A conversion of one whole value, given exactly its bytes; where they lay in the packets is the parser's concern. They may be a slice of a receive buffer, so a reader must copy any it keeps.

The bytes of a short Put of (at most, or it is slower) n bytes, in a buffer of that size: how a parameter's value is encoded by the put* functions below. binary's own runPut starts with a 4 KiB buffer, a large object of its own, and toStrict then copies the few bytes out of it: about 100 ns and 4 KiB per value.

decimal / numeric

type Precision = Word8 Source #

precisionToLength :: Precision -> Int Source #

Length of the magnitude (excluding the sign byte) for a given precision.

putDecimal :: Precision -> Scale -> Decimal -> Put Source #

A decimal at the precision and scale, rounded to the scale: the sign byte and precisionToLength bytes of magnitude.

readDecimal :: Precision -> Scale -> ValueReader Decimal Source #

decimal and numeric: a sign byte (0 negative, 1 positive) followed by a little-endian unsigned magnitude of 4, 8, 12 or 16 bytes (MS-TDS 2.2.5.5.1.3). The magnitude is usually precisionToLength bytes, but SQL Server doesn't always send that: a decimal(10,0) zero read from a table has 4, and a decimal(1,0) in a sql_variant has 16. So any of the four lengths is accepted, as SqlClient accepts them, and the value is checked against the precision instead. Another length, another sign byte, or a magnitude with more digits than the precision allows is a Left.

readDecimalWith :: (Bool -> Word64 -> Word64 -> Scale -> a) -> Precision -> Scale -> ValueReader a Source #

decimal and numeric, checked as readDecimal checks them, passing the value's parts to the function: whether it is negative, the high and low 64 bits of its magnitude, and the scale. A zero is never negative, though the wire can carry one.

UCS-2 strings

decodeUtf16LE :: ByteString -> Text Source #

Decode UTF-16LE text from the server, never failing.

SQL Server stores and sends UCS-2 code units without validating them, so a value can hold unpaired surrogates (NCHAR(0xD800), a reversed pair, a high surrogate cut off at the end of a string). Following the Unicode Standard's recommended practice ("U+FFFD Substitution of Maximal Subparts", ch. 3), each ill-formed code unit becomes exactly one U+FFFD and every well-formed scalar value decodes unchanged. A trailing odd byte (a truncated code unit) also becomes one U+FFFD.

text's own decodeUtf16LE throws on such input, and its decodeUtf16LEWith resynchronizes byte by byte, emitting one U+FFFD per byte and then misreading the following units.

One pass writing UTF-8 into the Text array, eight ASCII units at a time (Hmssql.Tds.Utf16).

putUcs2 :: Text -> Put Source #

Write text as UTF-16LE without a length prefix.

putBVarChar :: Text -> Put Source #

B_VARCHAR: one-byte character count followed by UCS-2 text. Fails (with error) for text of more than 255 UTF-16 code units, which the length byte can't count; check with ucs2Length first.

putUsVarChar :: Text -> Put Source #

US_VARCHAR: two-byte character count followed by UCS-2 text. Fails (with error) for text of more than 65535 UTF-16 code units.

ucs2Length :: Text -> Int Source #

The length of text in UTF-16 code units, which is what B_VARCHAR and US_VARCHAR count (a character outside the BMP is two).
